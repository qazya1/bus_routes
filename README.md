# Маршрутки — каталог автобусных маршрутов

Desktop-приложение на **C++ / Qt Widgets** для ведения каталога маршрутов городских маршрутных такси: создание, редактирование, удаление и хранение записей о маршрутах с валидацией вводимых данных и постоянным сохранением на диск.

Разработано как учебный проект (данные об остановках — реальные точки Волгограда: Центральный рынок, Вокзал, Тракторозаводской рынок, ВолГУ и др.).

## Возможности

- **CRUD-операции над маршрутами**: создание, редактирование, сохранение и удаление записей через список (`QListWidget`) и панель редактирования.
- **Валидация номера маршрута** по маске из 7 цифр и одной буквы (кириллица/латиница) через `QRegExpValidator`.
- **Выбор начального и конечного пункта** из фиксированного списка остановок; конечный пункт автоматически исключает уже выбранный начальный.
- **Промежуточные остановки** — многострочный ввод с автоматической очисткой от дублей и от остановок, совпадающих с начальной/конечной точкой.
- **Тарификация**: стоимость проезда по одному району (чекбокс + `QSpinBox`) либо полная стоимость маршрута с зависимым диапазоном значений.
- **Время в пути** через `QTimeEdit`.
- **Массовое создание записей**:
  - кнопка «Создать 10» — быстрое наполнение каталога 10 тестовыми маршрутами;
  - кнопка «Создать N» — открывает модальный диалог (`Dialog`), где пользователь задаёт произвольное количество записей для генерации, с итоговым отчётом через `QMessageBox`.
- **Автосортировка** записей в каталоге по идентификатору при вставке/обновлении.
- **Персистентное хранилище**: каталог сохраняется в бинарный файл `source.txt` и автоматически загружается при следующем запуске; запись закрытия окна (`closeEvent`) гарантирует сохранение данных.
- **Корректная работа с кириллицей** при сериализации — явное перекодирование строк в UTF-8 через `QTextCodec`.

## Архитектура

Проект разделён на слои с чёткой ответственностью:

| Модуль | Назначение |
|---|---|
| `catalog` (`catalog.h/.cpp`, `catalog.ui`) | Главное окно приложения (`QMainWindow`): UI-логика, обработка сигналов/слотов, синхронизация формы редактирования со списком записей |
| `catalogdb` (`catalogdb.h/.cpp`) | Слой доступа к данным: хранение записей в `QList<element>`, добавление/удаление/обновление, сортировка по позиции, сохранение и загрузка из файла |
| `element` (`element.h/.cpp`) | Доменная модель одной записи маршрута (номер, пункты, промежуточные остановки, тарифы, время в пути, ID); реализует побайтовую сериализацию через `QDataStream` и низкоуровневый ввод-вывод через WinAPI (`CreateFile`/`ReadFile`/`WriteFile`) |
| `tableItem` (`tableitem.h`) | Облегчённая DTO-структура для отображения записи в списке, без полной модели `element` |
| `Dialog` (`dialog.h/.cpp`, `dialog.ui`) | Вспомогательное модальное окно для пакетного создания N записей, передаёт данные в главное окно через сигнал `sendData` |

Такое разделение (модель `element` / доступ к данным `catalogdb` / UI `catalog`) соответствует паттерну, близкому к MVC, и облегчает независимое тестирование логики хранения от интерфейса.

## Технологический стек

- **Язык**: C++11
- **Фреймворк**: Qt 5.14.2 (модули `core`, `gui`, `widgets`)
- **UI**: формы Qt Designer (`.ui`), собираются в код через `uic`
- **Сборка**: `qmake` (файл проекта `bus_routes.pro`)
- **Хранение данных**: собственный бинарный формат на основе `QDataStream`, запись/чтение файла через нативный Windows API

## Сборка и запуск

Требуется Qt 5.14.2 (или совместимая версия Qt5) с модулем Widgets и компилятор с поддержкой Windows API (проект использует `<windows.h>` для файлового ввода-вывода, поэтому сборка возможна только под Windows — MinGW или MSVC).

```bash
qmake bus_routes.pro
make      # либо сборка через Qt Creator
```

После первого запуска приложение создаёт/использует файл `source.txt` в рабочей директории для хранения каталога маршрутов.

## Известные ограничения

- Хранилище данных завязано на WinAPI (`HANDLE`, `CreateFile`), что делает проект платформозависимым, несмотря на кроссплатформенность самого Qt.
- Данные хранятся в оперативной памяти (`QList`) и полностью сериализуются в файл при закрытии — SQL-БД не используется.
- Список остановок зашит в код (не редактируется через интерфейс).
